# Tarefa 13 — `std::regex` → `RegExp`

## Contexto do projeto

Syntax Bridge é uma IDE que transpila C/C++ para Dart. Servidor em Rust
(`crates/server/`), cliente Flutter. Leia `AGENTS.md` na raiz antes de começar —
ele é normativo (TDD obrigatório; `dynamic` proibido; quando não houver
equivalente direto em Dart, a resposta é uma fronteira/adaptador nomeado e
explícito, nunca um apagamento).

Use as receitas do `justfile`, não `cargo` cru. `just test` roda a suíte dentro
do Flatpak; `just test-host` roda na máquina quando o Flatpak não estiver
disponível (registre isso no resumo final).

Diagnóstico de origem: `docs/plans/estado-da-transpilacao-verovio-6.2.md`,
família **T13**. Este prompt é autocontido.

Esta é a família com o mapeamento **mais direto** de todo o backlog: C++ e Dart
usam a mesma sintaxe de expressão regular (ECMAScript) no subconjunto que o
Verovio usa.

## A causa raiz

Nenhum tipo de `<regex>` tem mapeamento. `std::regex` é
`Type::Unsupported("std::basic_regex")`, `std::smatch` é
`Type::Unsupported("std::match_results")`, e as funções livres
`std::regex_search`/`regex_replace`/`regex_match` não estão na tabela de
adaptadores de função livre (`BRIDGED_STDLIB_FREE_FUNCTION_NAMES`,
`crates/server/src/lower/cpp.rs:9959`).

Consequência: toda função que usa regex vira, no melhor caso, uma cadeia de
bailouts; no pior, um método inteiro em `UnimplementedError`.

## A evidência

Tipos sem mapeamento, do snapshot `.diagnosis/verovio-6.2.0.json`
(commit `32dd1df`):

É a ferramenta principal de parsing do humlib e do PAE.

## O que fazer

### 1. O mapeamento de tipo

| C++ | Dart |
| --- | --- |
| `std::regex` / `std::basic_regex<char>` | `RegExp` |
| `std::smatch` / `std::match_results<...>` | `RegExpMatch?` |
| `std::ssub_match` | `String?` |
| `std::regex_constants::syntax_option_type` | ver item 3 |
| `std::regex_constants::match_flag_type` | ver item 3 |

`RegExp` é uma classe do `dart:core` — nenhum import necessário. Trate-a como
um `Type::Record` com `usr` sintético, do mesmo jeito que
`SyntaxBridgeNativeHandle` já é tratado, ou introduza um `Type::Regex` se isso
ficar mais limpo; o importante é que ela **não** seja `Type::Unsupported`.

### 2. As operações

| C++ | Dart |
| --- | --- |
| `std::regex re("a(b)c")` | `final re = RegExp(r'a(b)c')` |
| `std::regex_search(s, m, re)` | `m = re.firstMatch(s); m != null` |
| `std::regex_match(s, m, re)` | uma correspondência ancorada — ver item 4 |
| `std::regex_replace(s, re, rep)` | `s.replaceAll(re, rep)` |
| `m[0]` | `m.group(0)` (idem para `m.str(0)`) |
| `m[n]` (n > 0) | `m.group(n)` |
| `m.size()` | `m.groupCount + 1` |
| `m.prefix()` / `m.suffix()` | ver item 4 |
| `std::sregex_iterator` | `re.allMatches(s)` |

Repare que `regex_search` no C++ devolve `bool` **e** preenche `m` — dois
efeitos numa expressão. Em Dart isso é uma atribuição seguida de um teste. O
produto já tem o mecanismo para "uma chamada que também escreve num local":
a ponte de out-param e o `ir::Stmt::TupleAssign`. Use-a, em vez de inventar
outra forma.

### 3. As flags

`std::regex_constants::icase` → `RegExp(..., caseSensitive: false)`;
`std::regex_constants::multiline` → `multiLine: true`. As demais
(`ECMAScript`, `optimize`, `nosubs`, `match_not_bol`, …) não têm equivalente e
devem virar **bailout explícito nomeando a flag** — nunca ser ignoradas em
silêncio, o que mudaria o comportamento sem avisar.

### 4. Escopo — o que fica de fora

Bailout explícito e específico para:

- `regex_match` (que exige correspondência da string **inteira**) — a tradução
  correta é envolver o padrão em `^(?:...)$`, o que só é seguro se o padrão não
  tiver alternância no topo. Meça quantos casos o Verovio tem antes de decidir:
  se forem poucos, bailout; se forem muitos, faça a análise do padrão.
- `m.prefix()` / `m.suffix()` — traduzíveis com `m.start`/`m.end` e `substring`;
  faça só se o corpus usar.
- `std::regex_traits` customizado, `basic_regex<wchar_t>`, `regex_iterator` com
  flags.
- Diferenças de sintaxe entre ECMAScript do C++ e o do Dart: `\b` dentro de
  classe de caracteres, back-references nomeadas, lookbehind. **Não tente
  reescrever padrões.** Se um padrão for um literal de string, ele passa
  direto; se for construído em tempo de execução, também. Registre no resumo
  que a equivalência de sintaxe é assumida, não verificada.

## Método

TDD, conforme `AGENTS.md`:

1. **Teste que falha primeiro**, o idioma do humlib:

   ```cpp
   #include <regex>
   #include <string>

   bool temNota(const std::string &s) {
       std::regex re("([A-G])([#b]?)([0-9])");
       std::smatch m;
       if (std::regex_search(s, m, re)) {
           return m[1] == "C";
       }
       return false;
   }

   std::string limpa(const std::string &s) {
       std::regex espacos("\\s+");
       return std::regex_replace(s, espacos, " ");
   }
   ```

   Verifique que nenhuma das duas vira bailout e que o Dart emitido usa
   `RegExp`.

2. **Teste comportamental — obrigatório aqui.** Uma regex que compila e casa
   diferente é exatamente o tipo de erro silencioso que o `AGENTS.md` proíbe.
   Acrescente os dois casos a `examples/E05-biblioteca-padrao/oracle/cases.json`
   (ou a um degrau novo) com entradas que exercitem grupos e substituição, para
   que o resultado seja **executado** nas duas linguagens e comparado.

3. **Teste da flag não suportada**: `std::regex re("a", std::regex_constants::nosubs);`
   tem de virar bailout com a flag nomeada na mensagem.

4. Implemente até passar. `just test` (ou `just test-host`, registrando),
   `just check`, `just lint`.

  **→ 0**.
- Erros do `dart analyze` podem subir em `humlib.dart`/`iohumdrum.dart`/
  `iopae.dart` — registre e classifique.

## Quando parar e perguntar

Só por decisão de **produto**: se, ao medir, o Verovio usar `regex_match` ou
padrões com construções que o Dart não aceita em volume, a escolha entre
"traduzir o padrão" e "bailout" é do produto. Traga a lista dos padrões
problemáticos, não uma estimativa.

Dificuldade técnica não é motivo para parar.
